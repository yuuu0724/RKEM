# 控制下位机数据流与 CRC 校验说明

## 1. 适用范围

本文说明 `main_process` 通过电机串口向控制下位机发送运动指令时的数据流、帧格式和 CRC 计算方法。默认通信口为 `/dev/ttyS8`，串口参数为 115200、8 数据位、1 停止位、无奇偶校验（115200 8N1）。

> 注意：8N1 中的“无校验”指 UART 硬件奇偶校验关闭，与应用层距离帧中的 CRC16 不冲突。

## 2. 下发数据流

运动控制的主要调用链如下：

```text
HMI 手动操作 / 检测流程 / 分拣流程
        |
        v
sendMotorCommand() 或 sendMotorDistanceCommand()
        |
        |  检查串口状态、上一条指令是否完成、距离是否合法
        v
sendMotorDistanceFrame()
        |
        |  距离转换为 2 字节大端数据
        v
buildEmployeeFrame()
        |
        |  添加帧头、命令字、长度、CRC16 和帧尾
        v
SerialPort::Send() -> /dev/ttyS8 -> 控制下位机
```

当前下位机支持单帧下发任意整数毫米距离。上层要求运动 55 mm 时，主机直接发送一帧距离为 55 mm 的指令，等待下位机返回一次完成帧后，将整个运动请求标记为完成。

距离范围为 1 至 65535 mm，不再要求是 20 mm 的整数倍。

主机在同一时刻只保留一条待完成的运动指令；等待超过 5 s 后，新请求可清理超时状态并重新下发。

## 3. 帧格式

### 3.1 带距离参数的完整帧

`0x25` 前进距离和 `0x26` 回退距离使用完整帧：

| 字段 | 长度 | 说明 |
| --- | ---: | --- |
| 帧头 | 2 字节 | 固定为 `AA 55` |
| 命令字 | 1 字节 | `25`=前进指定距离，`26`=回退指定距离 |
| 数据长度 | 2 字节 | 大端序，距离数据固定为 `00 02` |
| 数据区 | 2 字节 | 毫米数，16 位无符号整数，大端序 |
| CRC16 | 2 字节 | 对“命令字+数据长度+数据区”计算，帧内高字节在前 |
| 帧尾 | 1 字节 | 固定为 `FF` |

距离帧总长度固定为 10 字节：

```text
AA 55  CMD  00 02  DIST_H DIST_L  CRC_H CRC_L  FF
```

### 3.2 不带参数的短帧

部分控制命令和下位机回包使用 4 字节短帧：

```text
AA 55  CMD  FF
```

| 命令字 | 方向 | 含义 |
| --- | --- | --- |
| `20` | 主机 -> 下位机 | 兼容的前进命令 |
| `24` | 主机 -> 下位机 | 自动运行 |
| `21` | 下位机 -> 主机 | 前进/自动运行完成 |
| `22` | 下位机 -> 主机 | 回退完成 |
| `23` | 下位机 -> 主机 | 动作被按键中断 |

短帧按当前代码定义**不带 CRC**。下位机不应将 `AA 55 21 FF` 中的任何字节当作 CRC。

## 4. CRC 是怎么来的

代码使用的是 CRC-16/MODBUS 的位运算形式，参数为：

| 参数 | 值 |
| --- | --- |
| CRC 宽度 | 16 bit |
| 初始值 | `0xFFFF` |
| 反射多项式 | `0xA001` |
| 对应正向多项式 | `0x8005` |
| 输入处理 | 低位优先，每字节与 CRC 低 8 位异或 |
| 结果异或值 | `0x0000` |

计算范围从命令字开始，到数据区结束：

```text
不参与 CRC： AA 55
参与 CRC：   CMD LEN_H LEN_L DATA...
不参与 CRC： CRC_H CRC_L FF
```

与常见 Modbus RTU 传输习惯不同，本项目将计算结果按 **CRC 高字节、CRC 低字节** 的顺序放入帧中。下位机必须使用同样的字节序，不能直接套用“Modbus CRC 低字节先发”的打包方式。

与主机完全一致的 C 参考实现如下：

```c
#include <stddef.h>
#include <stdint.h>

uint16_t control_crc16(const uint8_t *data, size_t len)
{
    uint16_t crc = 0xFFFF;

    for (size_t i = 0; i < len; ++i) {
        crc ^= data[i];
        for (int bit = 0; bit < 8; ++bit) {
            if (crc & 0x0001) {
                crc = (uint16_t)((crc >> 1) ^ 0xA001);
            } else {
                crc = (uint16_t)(crc >> 1);
            }
        }
    }
    return crc;
}
```

打包时使用：

```c
uint16_t crc = control_crc16(&frame[2], 1 + 2 + payload_len);
frame[5 + payload_len] = (uint8_t)(crc >> 8);   /* CRC_H */
frame[6 + payload_len] = (uint8_t)(crc & 0xFF); /* CRC_L */
```

## 5. 计算示例

### 5.1 前进 20 mm

CRC 输入字节为：

```text
25 00 02 00 14
```

`0x0014` 是 20 的 16 位大端表示。按上述算法得到：

```text
CRC = 0x08C8
```

每处理完一个输入字节后的 CRC 中间值如下，可用于对照下位机程序：

| 已处理字节 | CRC 中间值 |
| --- | --- |
| 初始状态 | `FFFF` |
| `25` | `9B7E` |
| `25 00` | `201B` |
| `25 00 02` | `CAE1` |
| `25 00 02 00` | `480A` |
| `25 00 02 00 14` | `08C8` |

因此主机实际发送的完整帧为：

```text
AA 55 25 00 02 00 14 08 C8 FF
```

### 5.2 回退 20 mm

CRC 输入字节为：

```text
26 00 02 00 14
```

计算结果为 `0x088C`，完整帧为：

```text
AA 55 26 00 02 00 14 08 8C FF
```

### 5.3 其他校验向量

| 操作 | CRC 输入 | CRC 结果 | 完整发送帧 |
| --- | --- | --- | --- |
| 前进 100 mm | `25 00 02 00 64` | `ECC9` | `AA 55 25 00 02 00 64 EC C9 FF` |
| 回退 100 mm | `26 00 02 00 64` | `EC8D` | `AA 55 26 00 02 00 64 EC 8D FF` |

## 6. 下位机接收和校验建议

下位机收到完整距离帧后，建议按以下顺序处理：

1. 查找帧头 `AA 55`。
2. 读取命令字和两字节大端数据长度。
3. 等待完整的 `8 + payload_len` 字节到达。
4. 检查最后一字节是否为 `FF`。
5. 对 `CMD LEN_H LEN_L DATA...` 重新计算 CRC16。
6. 将计算值的高、低字节分别与帧内 `CRC_H CRC_L` 比较。
7. CRC 通过后再解析距离并执行运动；CRC 失败时丢弃该帧，不应驱动执行机构。
8. 执行完成后，前进返回 `AA 55 21 FF`，回退返回 `AA 55 22 FF`；中断时返回 `AA 55 23 FF`。

串口是字节流，一次读取不保证刚好得到一帧。下位机应使用接收缓冲区处理拆帧、粘帧和无效字节，不要假设一次 UART 接收中断就对应一条完整指令。
